Visualizador de Decisões Arquiteturais (ADRs)

ADR 0003: Write-Behind via Bounded Channels com Flush em Lote

Status: Aceita • Contexto: O caminho crítico de redirecionamento (GET /{code}) exigia latência inferior a 5ms. Gravar cliques sincronicamente no PostgreSQL derrubaria o banco e aumentaria a latência para dezenas de milissegundos.

// Decisão de Engenharia:
Channel<ClickEvent> com BoundedCapacity(50.000) e FullMode = DropOldest.
O endpoint chama TryWrite() (sem bloqueio de thread).
BackgroundService descarrega em lotes de 100 itens ou a cada 5 segundos.

Trade-off assumido: Semântica at-most-once. Prioriza-se a disponibilidade total do redirect em vez da perda de analytics sob sobrecargas extremas.

ADR 0004: Negative Caching com Sentinela e Jitter

Status: Aceita • Contexto: Evitar Cache Penetration (ataques que buscam URLs inexistentes para exaurir o Postgres) e Cache Stampede (múltiplas chaves expirando no mesmo segundo).

// Solução:
1. Negative Cache: se a URL não existe, grava __NOT_FOUND__ com TTL de 60s no Redis.
2. Jitter: TTL base de 24h + variação aleatória de 0 a 1800s para dispersar expirações.
3. Strings brutas: zero overhead de serialização JSON no caminho crítico.

OrderEngine: Atomicidade via Transactional Outbox Pattern

Status: Aceita • Contexto: Eliminar transações distribuídas (2PC) caras entre PostgreSQL e RabbitMQ, garantindo que nenhum pedido fique pago sem o respectivo evento despachado.

// Mecanismo:
Order e OutboxMessage são persistidos no mesmo SaveChangesAsync (Transação ACID).
OutboxBackgroundService faz pooling a cada 5s, publica no RabbitMQ e marca ProcessedOn.
Consumidores implementam Idempotência no Redis + Double-Check no PostgreSQL com Dead Letter Queue (DLQ).

Metodologia SDD: Governança Estrita de Agentes de IA

O Spec-Driven Development é a resposta técnica para evitar vibe coding e alucinações de modelos de linguagem.

  • SPEC.md: Requisitos não-funcionais, regras e códigos HTTP antes do código.
  • constitution.md: Leis invioláveis de engenharia (ex.: proibições de chamadas síncronas em redirects).
  • TASK.md: Execução em passos atômicos, validando compilação e testes a cada commit.
